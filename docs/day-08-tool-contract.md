# Day 8：描述一個可被 AI 理解的操作

以下是從「幫我找下週的前端活動」整理出的**草稿規格卡**。它用來練習描述能力；Day 13 才會把正式 `search_events` contract 納入 Demo。

| 欄位 | 草稿內容 |
|---|---|
| 名稱 | `search_events` |
| 目的 | 依使用者提供的關鍵字，找出可參加的公開活動摘要。 |
| 適用時機 | 使用者想探索活動，但尚未決定要看哪一場詳情。 |
| 輸入 | `query`：非空白的活動主題、地點或類別關鍵字。 |
| 成功結果 | 活動摘要陣列；每筆包含標題、日期、地點與不透明活動識別碼。 |
| 查無資料 | 空陣列與可供 Agent 回覆使用者的說明。 |
| 限制 | 只搜尋目前公開資料；不執行收藏、報名或付款。 |
| 副作用 | 無；這是讀取型候選能力。 |

## 模糊規格的反例

「按搜尋，再看活動卡片」不是 Tool contract。它只描述人類目前如何操作畫面，沒有說明 Agent 應在什麼情況使用、輸入的意義、結果形狀與副作用。
